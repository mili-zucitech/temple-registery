1. PURPOSE

   Registry of all planned REST API endpoints. Serves as the contract between
   backend and frontend teams. Formal OpenAPI/Swagger spec to be generated
   from Spring Boot annotations; this document is the planning baseline.

--------------------------------------------------------------------------------

3. DETAILED CONTENT

   3.1 CONVENTIONS

   - Base URL: /api/v1
   - All endpoints return: ResponseEntity<ApiResponse<T>>
   - ApiResponse<T>:  { success: bool, data: T, error: string|null,
                        timestamp: ISO8601, requestId: UUID }
   - Auth: Bearer token in Authorization header (all endpoints except /auth/**)
   - Pagination: { page, size, sort } query params; response includes { totalElements }
   - Error codes: HTTP 400 (validation), 401 (unauth), 403 (forbidden),
                  404 (not found), 409 (conflict), 500 (server error)

   POST /api/auth/login REQUEST / RESPONSE:
   Request:  { "username": "string", "password": "string" }
   Response (MFA required):
     HTTP 200 { "mfaRequired": true, "tempToken": "opaque-uuid",
                "challengeType": "TOTP|SMS_OTP", "expiresIn": 300 }
   Response (account locked):
     HTTP 423 { "error": { "code": "TRM-AUTH-004", "message": "...",
                           "retryAfter": "ISO8601-datetime" } }

   POST /api/auth/mfa-verify REQUEST / RESPONSE:
   Request:  { "tempToken": "string", "mfaCode": "6-digit string",
               "isRecoveryCode": false }
   Response HTTP 200:
     { "accessToken": "RS256 JWT", "expiresIn": 900,
       "user": { "id": long, "username": "string", "role": "DISTRICT_COLLECTOR",
                 "districtId": long|null, "templeId": long|null,
                 "mfaReenrollmentRequired": bool } }
   Set-Cookie: refreshToken=<opaque-uuid>; HttpOnly; Secure; SameSite=Strict; Path=/api/auth/refresh

   POST /api/auth/mfa-setup RESPONSE:
   HTTP 200 { "totpSecret": "BASE32-encoded-secret",
              "qrCodeUri": "otpauth://totp/TRM:{username}?secret=...&issuer=TRM",
              "setupToken": "opaque-uuid" }
   NOTE: setupToken is a short-lived (10-min) token used only for the confirm step.
   The user scans the QR code with their authenticator app before calling confirm.

   POST /api/auth/mfa-setup/confirm REQUEST / RESPONSE:
   Request:  { "setupToken": "string", "mfaCode": "6-digit string" }
   Response HTTP 200:
     { "recoveryCodes": ["string x 8"], "message": "MFA configured successfully.
       Store these recovery codes in a safe place. They will not be shown again." }
   Service logic:
     1. Verify setupToken is valid and not expired
     2. Verify mfaCode against the TOTP secret stored in the setup session
     3. UPDATE users SET mfa_enabled = 1, mfa_type = 'TOTP' WHERE id = :userId
     4. INSERT 8 rows into mfa_recovery_codes (bcrypt-hashed)
     5. Invalidate setupToken
     6. Return raw recovery codes ONCE (never stored in plaintext; never returned again)

   Param              | Type    | Required | Notes
   -------------------|---------|----------|----------------------------------------------
   page               | int     | No       | Default 0

   sort               | string  | No       | e.g. 'temple_name,asc'
   district_id        | long    | DC role: YES | Auto-populated from JWT claim for DC; ignored if provided by DC (JWT wins)
   taluk_id           | long    | No       | Optional sub-district filter (PARTIAL GEO SELECTION SUPPORTED)
   hobli_id           | long    | No       | Optional hobli filter (PARTIAL GEO SELECTION SUPPORTED)
   grade              | string  | No       | Values: A, B, C (comma-separated for multi-select e.g. 'A,B'); omit for All Grades
   keyword            | string  | No       | Partial match on temple_name
   deityName          | string  | No       | Case-insensitive LIKE match on deity_name
   tradition          | string  | No       | Exact match: SHAIVITE, VAISHNAVITE, SHAKTA, JAIN, BUDDHIST, OTHER
   trustRegistered    | boolean | No       | true=only trusted temples, false=untrusted
   declarationStatus  | string  | No       | PENDING, APPROVED, OVERDUE (maps to summary counters)
   establishedYearFrom| int     | No       | Inclusive lower bound (e.g. 1200)
   establishedYearTo  | int     | No       | Inclusive upper bound (e.g. 1900)

   PARTIAL GEO SELECTION: All geo parameters (taluk_id, hobli_id) are individually
   optional. A DC can search at district level only (taluk_id absent = search entire
   district). SQL pattern for partial geo scope:
     WHERE t.hobli_id IN (
       SELECT h.id FROM geo_hoblis h
       JOIN geo_taluks tal ON tal.id = h.taluk_id
       WHERE (:talukId IS NULL OR tal.id = :talukId)
       AND (:hobliId IS NULL OR h.id = :hobliId)
       AND tal.district_id = :districtId
     )
   This correctly returns all temples in the district when taluk_id is omitted.

   GRADE MULTI-SELECT: comma-separated for multiple grades:
     ?grade=A,B  --> filter for Grade A and Grade B only
     (omit grade param entirely = "All Grades" equivalent)

   3.9 DOCUMENT ENDPOINTS

   Method | Path                      | Role          | Description
   -------|---------------------------|---------------|------------------------
   POST   | /api/documents/upload     | TA, SA        | Upload PDF document
   GET    | /api/documents/{id}/url   | DC, TA, SA    | Get pre-signed download URL
   GET    | /api/documents/{id}       | DC, TA, SA    | Document metadata

   GET /api/documents/{id}/url ACCESS CONTROL (enforced before S3 pre-sign):
   Before generating the pre-signed URL the service MUST:
     1. Load the document record; check documents.is_deleted = 0
     2. If caller role = TEMPLE_AUTHORITY:
          assert documents.temple_id = caller.temple_id (403 if mismatch)
     3. If caller role = DISTRICT_COLLECTOR or DC_STAFF:
          JOIN to get temple.district_id; assert district_id = caller.district_id (403 if mismatch)
     4. INSERT INTO document_access_log (document_id, accessed_by, access_type='DOWNLOAD',
          accessed_at=NOW(), role=caller.role)
     5. Return pre-signed URL with 15-minute expiry
   Failure to pass any check returns 403 Forbidden (no stack trace in body).

   3.12 ADMIN ENDPOINTS (SUPER_ADMIN only)

   Method | Path                                          | Role | Description
   -------|-----------------------------------------------|------|------------------------------------------
   PATCH  | /api/admin/users/{id}/district                | SA   | Transfer DC to new district (atomically updates district_id + token_revoked_before + revokes all refresh tokens)
   PATCH  | /api/admin/declarations/{id}/force-draft      | SA   | Return PENDING_REVIEW -> DRAFT (TA withdrawal use-case; SA only; logged in audit trail)
   POST   | /api/admin/notifications/{id}/retry           | SA   | Retry a FAILED notification event

   GET    | /api/admin/declarations/physical-verification-pending | SA | List declarations in PHYSICAL_VERIFICATION_REQUESTED > 30 days

   PATCH /api/admin/users/{id}/district REQUEST BODY:
     { newDistrictId: long (required), reason: "string max 500 chars" (required for audit) }
   Service atomically performs:
     1. UPDATE users SET district_id = :newDistrictId, token_revoked_before = NOW(6)
     2. UPDATE refresh_tokens SET revoked_at = NOW(6) WHERE user_id = :id
     3. INSERT audit_data_events (operation=UPDATE, action=DISTRICT_REASSIGNMENT, before/after values)
   Response: 200 OK

   PATCH /api/admin/declarations/{id}/force-draft REQUEST BODY:
     { reason: "string max 500 chars" (required) }
   Guard: declaration.status must be PENDING_REVIEW (not APPROVED or REJECTED).
   Transitions: PENDING_REVIEW -> DRAFT, stores reason in review_comment field.
   Use case: Temple Authority submitted for wrong financial year; SUPER_ADMIN use only.

     HTTP 200
     Content-Type:        application/csv  OR  application/pdf
     Content-Disposition: attachment; filename="temples_export_YYYYMMDD_HHMMSS.csv"
     Body:                Direct file byte stream

   EXPORT RESPONSE — ASYNC (record count > 500 rows):
     HTTP 202 Accepted
     Body: {
       "jobId":   "UUID",
       "message": "Export request queued. A download link will be sent to your registered email address.",
       "estimatedRows": int
     }
     Behaviour: ExportJobService enqueues job; @Scheduled worker generates file, uploads
     to storage gateway, and fires EMAIL notification with a 24-hour pre-signed download link.
     NOTE: The async threshold is 500 rows. Below 500, always respond synchronously
     (no job queue needed). This decision avoids infrastructure complexity for small exports.

   TEMPLE EXPORT FIELD LIST (CSV column order / PDF table columns):

     Deity Name | Religious Tradition | Established Year | Trust Registered (Y/N) |

   EXPORT JURISDICTION SCOPING (MANDATORY):
   For DC and DC_STAFF roles, all export queries MUST apply the same
   district_id scoping as the search endpoint (district_id = JWT claim value).
   SUPER_ADMIN exports are unscoped (all districts).
   A DC must never receive data from outside their assigned district in an export.

   EXPORT AUDIT LOGGING (MANDATORY):
   On every successful export generation, INSERT into audit_export_events:
     user_id, role, district_id (null for SA), export_type ('TEMPLES' or 'DECLARATIONS'),
     record_count (number of rows exported), filters_applied_json (the request body),
     generated_at = NOW(6)

4. DECISIONS LOCKED

   - All endpoints return ApiResponse<T> wrapper (never raw entity)
   - Pagination via Spring Pageable (page/size/sort query params)
   - Document upload is a separate single endpoint; linked to module entity
     by separate junction table entries
   - DELETE is soft-delete for employees and contractors; no hard DELETE API
