1. PURPOSE

   Registry of all planned REST API endpoints. Serves as the contract between
   backend and frontend teams. Formal OpenAPI/Swagger spec to be generated
   from Spring Boot annotations; this document is the planning baseline.

--------------------------------------------------------------------------------

3. DETAILED CONTENT

   3.1 CONVENTIONS

   - Base URL: /api/v1
   - All endpoints return: ResponseEntity<ApiResponse<T>>
   - ApiResponse<T>:  { success: bool, data: T, error: string|null,
                        timestamp: ISO8601, requestId: UUID }
   - Auth: Bearer token in Authorization header (all endpoints except /auth/**)
   - Pagination: { page, size, sort } query params; response includes { totalElements }
   - Error codes: HTTP 400 (validation), 401 (unauth), 403 (forbidden),
                  404 (not found), 409 (conflict), 500 (server error)

   Method | Path                        | Role          | Description
   -------|-----------------------------|---------------|---------------------------
   GET    | /api/temples                | DC, SA        | Search temples (with filters)
   POST   | /api/temples                | TA, SA        | Create temple
   GET    | /api/temples/{id}           | DC, TA, SA    | Get temple detail
   PUT    | /api/temples/{id}           | TA (own), SA  | Update temple basic info
   GET    | /api/temples/{id}/profile   | DC, TA, SA    | Get current profile
   POST   | /api/temples/{id}/profile/staging | TA, SA  | Create/update staging profile
   POST   | /api/temples/{id}/profile/submit  | TA      | Submit staging for review

   GET    | /api/temples/{id}/profile/history | DC, TA, SA | Profile version history

   GET /api/temples QUERY PARAMETERS:
   Param              | Type    | Required | Notes
   -------------------|---------|----------|----------------------------------------------
   page               | int     | No       | Default 0
   size               | int     | No       | Default 25; max 100
   sort               | string  | No       | e.g. 'temple_name,asc'
   district_id        | long    | DC role: YES | Auto-populated from JWT claim for DC
   taluk_id           | long    | No       | Optional sub-district filter
   hobli_id           | long    | No       | Optional hobli filter
   grade              | string  | No       | Values: A, B, C (comma-separated for multi)
   keyword            | string  | No       | Partial match on temple_name
   deityName          | string  | No       | Case-insensitive LIKE match on deity_name
   tradition          | string  | No       | Exact match: SHAIVITE, VAISHNAVITE, SHAKTA, JAIN, BUDDHIST, OTHER
   trustRegistered    | boolean | No       | true=only trusted temples, false=untrusted
   declarationStatus  | string  | No       | PENDING, APPROVED, OVERDUE (maps to summary counters)
   establishedYearFrom| int     | No       | Inclusive lower bound (e.g. 1200)
   establishedYearTo  | int     | No       | Inclusive upper bound (e.g. 1900)

   SCOPING RULE: For DC and DC_STAFF roles, district_id is always enforced
   from the JWT claim (even if provided in query param, JWT value wins).
   SUPER_ADMIN may omit district_id to search across all districts.

   3.8 DECLARATION ENDPOINTS

   Method | Path                                             | Role    | Description
   -------|--------------------------------------------------|---------|--------------------
   GET    | /api/temples/{id}/declarations                   | DC,TA,SA| List declarations
   POST   | /api/temples/{id}/declarations                   | TA, SA  | Create DRAFT
   GET    | /api/declarations/{id}                           | DC,TA,SA| Declaration detail
   PUT    | /api/declarations/{id}                           | TA (own)| Update DRAFT fields
   POST   | /api/declarations/{id}/submit                    | TA (own)| DRAFT->PENDING_REVIEW
   POST   | /api/declarations/{id}/approve                   | DC, SA  | PENDING_REVIEW->APPROVED
   POST   | /api/declarations/{id}/reject                    | DC, SA  | PENDING_REVIEW or PHYSICAL_VERIFICATION_REQUESTED->REJECTED
   POST   | /api/declarations/{id}/clarification             | DC, SA  | PENDING_REVIEW->CLARIFICATION_REQUESTED
   POST   | /api/declarations/{id}/flag-physical-verification| DC, SA  | PENDING_REVIEW->PHYSICAL_VERIFICATION_REQUESTED
   POST   | /api/declarations/{id}/resubmit                  | TA (own)| CLARIFICATION_REQUESTED->PENDING_REVIEW
   GET    | /api/declarations/{id}/diff                      | DC,TA,SA| Version diff
   GET    | /api/declarations/{id}/acknowledgement           | TA (own)| Download ack PDF (pre-signed URL)

   POST /api/declarations/{id}/flag-physical-verification REQUEST BODY:
     { "notes": "string (mandatory, max 2000 chars) -- reason for physical verification" }
   Response: 204 No Content on success.
   Guard: declaration.status must be PENDING_REVIEW; DC must be in same district.

   POST /api/declarations/{id}/resubmit REQUEST BODY:
     { "correction_notes": "string (mandatory, max 2000 chars) -- explains what was corrected",
       "[updated declaration fields as per PUT schema]" }
   Behaviour: Applies corrections to declaration fields, transitions CLARIFICATION_REQUESTED
     -> PENDING_REVIEW, logs correction_notes to declaration_clarifications
     (direction='TEMPLE_TO_DC').

   GET /api/declarations/{id}/acknowledgement:
   Returns: { "download_url": "pre-signed S3 URL (expires in 15 minutes)",
              "acknowledgement_number": "TRM/ACK/2025-26/000142",
              "generated_at": "ISO8601" }
   Guard: declaration.status must be APPROVED; TA must own the temple, DC must be in district.

   3.9 DOCUMENT ENDPOINTS

   Method | Path                      | Role          | Description
   -------|---------------------------|---------------|------------------------
   POST   | /api/documents/upload     | TA, SA        | Upload PDF document
   GET    | /api/documents/{id}/url   | DC, TA, SA    | Get pre-signed download URL
   GET    | /api/documents/{id}       | DC, TA, SA    | Document metadata

   GET /api/documents/{id}/url ACCESS CONTROL (enforced before S3 pre-sign):
   Before generating the pre-signed URL the service MUST:
     1. Load the document record; check documents.is_deleted = 0
     2. If caller role = TEMPLE_AUTHORITY:
          assert documents.temple_id = caller.temple_id (403 if mismatch)
     3. If caller role = DISTRICT_COLLECTOR or DC_STAFF:
          JOIN to get temple.district_id; assert district_id = caller.district_id (403 if mismatch)
     4. INSERT INTO document_access_log (document_id, accessed_by, access_type='DOWNLOAD',
          accessed_at=NOW(), role=caller.role)
     5. Return pre-signed URL with 15-minute expiry
   Failure to pass any check returns 403 Forbidden (no stack trace in body).

   3.11 EXPORT ENDPOINTS

   Method | Path                  | Role         | Description
   -------|-----------------------|--------------|------------------------
   POST   | /api/export/temples   | DC, SA       | Export temple list (PDF/CSV)
   POST   | /api/export/declarations | DC, SA    | Export declarations (PDF/CSV)

   EXPORT JURISDICTION SCOPING (MANDATORY):
   For DC and DC_STAFF roles, all export queries MUST apply the same
   district_id scoping as the search endpoint (district_id = JWT claim value).
   SUPER_ADMIN exports are unscoped (all districts).
   A DC must never receive data from outside their assigned district in an export.

   EXPORT AUDIT LOGGING (MANDATORY):
   On every successful export generation, INSERT into audit_export_events:
     user_id, role, district_id (null for SA), export_type ('TEMPLES' or 'DECLARATIONS'),
     record_count (number of rows exported), filters_applied_json (the request body),
     generated_at = NOW(6)

4. DECISIONS LOCKED

   - All endpoints return ApiResponse<T> wrapper (never raw entity)
   - Pagination via Spring Pageable (page/size/sort query params)
   - Document upload is a separate single endpoint; linked to module entity
     by separate junction table entries
   - DELETE is soft-delete for employees and contractors; no hard DELETE API

5. OPEN QUESTIONS
